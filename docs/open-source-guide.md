# Open Source Guide

This guide explains how Praxys will be developed as an open source product.

## Open source goals

- build a community-driven productivity app
- make setup and contribution simple
- maintain transparent progress and planning
- publish documentation for users and contributors
- keep development public and welcoming

## Public vs. internal documentation

- `docs/` contains public-facing project documentation
- `dev_docs/` contains private development notes and planning
- `README.md` is the main entry point for users and contributors

Only publish `docs/` and `README.md` as part of the open source project. Keep internal drafts and private workflows in `dev_docs/` if they are not ready for public distribution.

## Planning cadence

### Weekly plan

- complete a focused set of improvements
- update public docs and roadmap status
- review issues and prioritize next work
- keep feature branches small and well-documented

### Monthly plan

- complete a broader milestone
- review progress against the roadmap
- polish public onboarding for new contributors
- gather feedback and adjust priorities

## Contributions and community

- treat external contributors as collaborators
- provide clear issue descriptions and labels
- keep pull requests easy to review
- document setup, architecture, and workflows

## Recommended public documentation

Use `docs/` for:

- getting-started instructions
- contribution guidelines
- roadmap and release plan
- open source launch notes
- any public API or architecture information

If more public documentation is needed, add new files under `docs/` and link them from `README.md`.
